Nuevo schema de sesión (Supabase)

La tabla sessions se reemplaza limpiamente con este schema simplificado.

-- Core
id UUID PRIMARY KEY DEFAULT gen_random_uuid()
created_at TIMESTAMPTZ DEFAULT NOW()
step INTEGER DEFAULT 0
-- Step 1: Referencia
reference_url TEXT ← Supabase Storage
reference_analysis JSONB
-- Step 2: Producto + preguntas
product_url TEXT ← Supabase Storage
logo_url TEXT ← Supabase Storage (opcional)
product_scan JSONB
product_name TEXT
what_it_does TEXT
target_audience TEXT
-- Step 3: Copy
tiktok_comments TEXT
copy_versions JSONB ← {versionA:[...], versionB:[...]}
-- Step 4: Confirmación
confirmed_copy JSONB ← {version:'A'|'B', breakdown:[...]}
-- Step 5: Resultado
edit_instruction TEXT
image_url TEXT ← Supabase Storage

Rutas API — lo que cambia

MANTIENE POST /api/sessions crear sesión
MANTIENE GET /api/sessions/[id] leer sesión
REEMPLAZA POST /api/sessions/[id]/analyze-reference
Upload → Supabase Storage → Gemini 2.5 Flash → ReferenceAnalysis JSON → session step=1
REEMPLAZA POST /api/sessions/[id]/analyze-product
Upload product + logo + {name, whatItDoes, audience} → Supabase Storage → Gemini scan → ProductScan JSON → session step=2
NUEVO POST /api/sessions/[id]/generate-copy
TikTok comments → Gemini 2.5 Flash → CopyVersions {A, B} → session step=3
SIMPLIFICA POST /api/sessions/[id]/confirm-copy
Body: {version: 'A'|'B'} → guarda confirmed_copy → session step=4
REEMPLAZA POST /api/sessions/[id]/generate-image
SSE stream: fetch images from Supabase Storage → base64 → Gemini editImage → save result → Supabase Storage
NUEVO POST /api/sessions/[id]/refine-image
Body: {feedback: string} → Gemini refineImage con resultado actual → nuevo image_url
